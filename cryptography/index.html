Yaksha

Experimental symmetric encryption: a deterministic primitive, parameters derived from the key, a neural-inspired mode, and a stateful authenticated wrapper. It is not a certified product, and it is not Val-Crypt.

Crate 1.0.0ProprietaryNot a security proof

Question How it is arranged Ocean Tests Val-Crypt Limits Documents

Research question

Can a parameterized symmetric construction separate a reversible transform, a session, and an integrity tag — and what do statistical batteries actually say about the bytes it emits?

How the crate is arranged

The library comment in yaksha-cipher 1.0.0 describes three layers. A stateful key derivation function differentiates sessions. The encryption primitive is deterministic: the same key and the same plaintext produce the same ciphertext at that layer. A MAC binds ciphertext and associated data. The public surface names four modes: core, parametric (parameters taken from the key), neural (described as MeshBrain-inspired), and aead (YakshaAead).

  1. 1YakshaKdf

    Session material. Uniqueness is a protocol property, not a property of the bare primitive.

  2. 2Primitive

    Core, parametric, or neural transform. The crate also contains vector and geometric modules marked legacy or experimental.

  3. 3YakshaMac

    Authentication on decrypt. A failed tag is an integrity failure, not a decryption of a different message.

The crate manifest depends on Rayon, so the parallel work in this version is CPU-side. It does not depend on a GPU toolkit. Throughput claims that require a GPU are not made on this page.

The README states avalanche and key sensitivity of about 50%. Those are diffusion measurements reported by the project. They are not a security reduction.

Ocean

ocean_pipeline.rs is a two-phase wrapper around a cipher body. Encrypt applies ocean phase one, then the body, then ocean phase two. Decrypt reverses that order. A session anchor is derived from the key. The wrapper is part of Yaksha. It is not the Val-Crypt paper.

Val-Crypt is a different construction

Val-Crypt is a separate public repository. Its README describes two reversible modes that share a cascade. Vector mode treats 4 bytes as a 4-dimensional vector and applies ARX quarter-rounds. Entropy mode chooses a per-byte transform from a deterministic entropy path, using odd multiplication so the step stays invertible modulo 256. The README reports, as author measurements, avalanche of 50.7% and 53.6%, and throughput of 885 MB/s and 888 MB/s. A January 2026 note in the private tree is a technical manuscript of that design. It is not peer reviewed on this site.

Some files inside the local yaksha-cipher directory are titled as Val-Crypt reports, including a scientific report dated 31 January 2026 that discusses prefix leakage, deterministic encryption, and a two-round ARX schedule. Those findings belong to that Val-Crypt write-up. They are not relabeled here as Yaksha results, and the two systems are not merged into one algorithm.

Val-Crypt repository. License stated there: MIT.

Limits

No independent cryptanalysis is claimed. A Dieharder pass is not a proof of confidentiality, authenticity, or misuse resistance. The crate is proprietary (LicenseRef-Proprietary-Rogue-Intelligence-LNC, publish = false). The repository URL in the manifest returned 404 when this page was written, so no public source link is offered for Yaksha.

The construction is not presented as FIPS validated, or as a replacement for a standardized AEAD.

Collaboration

Appropriate work is implementation review, an independent randomness battery on structured plaintexts, or a cryptanalysis that is allowed to fail. Licensing of the proprietary crate is a separate request. Contact.
