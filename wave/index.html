04 / Research · Rule-driven computing

Wave

A language that writes intent and combinations of rules. The compiler translates those combinations into machine behavior: an instruction, a call, a loop, a system call, or a GPU kernel.

Public language definitionThree alpha compilersMIT

Research question

Can machine behavior be specified as a combination of a small rule field, instead of as a list of instructions the programmer already chose?

The translation

The public Wave repository states the definition directly. A program writes intent and rule combinations, not one instruction at a time. Rules combine, the combination is translated, and the result is concrete behavior. The field has three parameters: i information density, e entropy gradient, and r relation strength.

  1. SourceIntent

    out, fn, when, loop, assignment, unified.

  2. Fieldi, e, r

    Three parameters. The compilers accept them as a unified block.

  3. RulesCombine

    Eight rules, derived from the field, compose.

  4. LowerBehavior

    x86-64, a system call, or an OpenCL-mapped kernel.

Copied from the public language README, including the stated derivation. This is the language’s model of itself.

The same page gives four lowerings: mov = gravitational + connection, add = entropy + gravitational, call = connection + boundary, loop = orbital + tension. GPU combinations are stated the same way: orbital with entropy for vector operations, gravitational for a reduction, entropy with gravitational for a dot product, orbital with orbital for a matrix product.

Three compilers, three jobs

All three public repositories are marked Alpha Test 1.0. They implement a shared surface: variables, arithmetic, comparisons, when, loop, functions, out, syscall.exit, and unified { i, e, r }. Wave-C and the assembly compilers also document Fate on/off.

ArtifactWhat it isWhat the README shows
Wave-CReference compiler in C.gcc -o wavec src/wave5.c. Documents a Fate scheduler and four tile-memory pools named BlackHole, MeshBrain, MultiNova, and BaseForce. Those pool names are not the Valhalla ingress cycle.
Wave-ASMThe compiler written in x86-64 assembly.NASM to an ELF64 binary, about 15 KB, syscalls only, no libc. Emits ELF64 for the user program.
Wave-BINThe compiler as a raw binary, no operating system required.nasm -f bin, 8 KB. Header magic WAVE, version 1, entry offset. A loader maps it and calls compile at offset 16.

GPU path

The Wave repository describes wave/gpu/host/ as the GPU line: rules lowered to OpenCL, with wave_gpu_host and a gpu.rule task syntax. The documented invocation is gpu on, a unified block, then gpu.rule orbital entropy op add size 256. A cross-language harness is described for a 10-million-iteration scalar loop against C and Python. The README does not print the timings, so this page does not invent them.

A program

From the public README, unchanged:

fn add a b {
    -> a + b
}

unified {
    i: 0.8
    e: 0.2
    r: 0.9
}

result = add(10, 20)
out "Hello, Wave!\n"
syscall.exit(0)

A local tree, Val-OS v5, is an operating-system experiment written in Wave: boot, kernel, and drivers as .wave sources. It is not a fifth research line, and it is not described here as a shipped operating system. An older local snapshot, Wave v4.3, talks about self-hosting and a hybrid interface. The public definition used on this page is the rule-translation README, not that snapshot.

Limits

Alpha means the compilers exist and the READMEs show a language surface. It does not mean a stable specification, a conformance suite published with results, or a general-purpose systems language ready to replace C.
