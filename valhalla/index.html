Valhalla

A session stores structure. Fate schedules signals into a body of Hub, Tile, and Stem. A language model can answer from that body. The model is not the body.

Research question

Can a system keep a task as an incubated structure — shared across text, speech, and image, able to abstain, and still readable after the language model is swapped — rather than as a growing prompt?

Central idea

The 14 July 2026 architecture note draws five layers. Ingress accepts text, speech features, image features, and appended session material. Fate schedules that material and can emit or abstain. The Triad body is Hub, Tile, and StemCell. Feedback returns into Fate. Readout is a native answer, with a language model drawn as a dashed, optional head.

  1. IngressOne session

    Modalities are pulses in the same session, not three stores fused at the end.

  2. Fatequad_cycle

    BlackHole, then MeshBrain, then MultiNova, then BaseForce.

  3. BodyHub, Tile, Stem

    Route, complete a local pattern, cluster toward organs. Fragments hold the compact structure.

  4. FeedbackContinuity

    Question-answer feedback and a persistent snapshot.

  5. ReadoutNative path

    Open questions can be answered from structure.

    Optional LM head. Default documented decoder: Qwen2.5-0.5B-Instruct, replaceable.

How a turn works

  1. 01
    Ingest

    Context lines and multimodal items build or extend an incubation snapshot. Appending changes the snapshot’s fingerprint.

  2. 02
    Route

    Production notes recommend fate_ingress_routing="quad_cycle" and fate question-answer feedback.

  3. 03
    Form structure

    Hub carries routing preference. Tile completes local pattern. StemCell clusters. The public formation record, protocol triad-structure-highlight-v1, reports 16 tiles, 108 stems, hub 104×4.

  4. 04
    Decode by question type

    Documented hybrid routing sends open questions to native retrieval and multiple choice to a model log-probability head. Structure-only multiple choice, on the cited 46-item scale, scored 35% against the model head’s 63%.

Names, and one collision

BlackHole, MeshBrain, MultiNova, and BaseForce are the four Fate ingress quadrants, in that order, in the Valhalla architecture note. Wave-C uses the same four names for tile-memory pools. This page does not treat those pools and this ingress cycle as one implementation.

Training notes describe three structure layers: session structure, Fate pretraining, and a weight bake. The fast scorecard reports a bake weight delta of about 298. That is a measurement of a write, not a claim that the model has been replaced.

The Windows shell

A local application, valhalla-lift-desktop, is a chat-first Windows shell over the Valhalla runtime. It is an application of the architecture, not a separate research line.

The chat surface sends a turn to valhalla_base. Settings has three panels. Knowledge is one fact per line, and chat retrieves from those lines. Models lists Qwen2.5 Instruct checkpoints, with download and use. General sets language (system, Chinese, or English), the answer strategy, and whether later questions keep the previous structure session.

Four strategies are named in the interface: faithful retrieval, hybrid multiple choice, follow-up session, and multi-hop. A self-test in the shell checks that an open item decodes on a native path, a multiple-choice item uses an LM patch, and a follow-up carries a second turn. That split is the product expression of the stack: open answers come from structure; multiple choice still uses a model head.

No interface capture is published on this site. Figures printed inside that desktop build are not repeated here; they do not match the 14 July public mirror line for line.

Limits

The public mirror explicitly does not claim a LoCoMo or LongMemEval win, or that Valhalla replaces a transformer.

On 27 June 2026, a progress snapshot reported that its holdout session snapshot did not exceed cold retrieval, and treated that as evidence against reading the runtime as a fine-tune substitute. July records add formation, topology, training, and unique-proof measurements. They are later, and they are different protocols.

Multiple choice still depends on the model head in the numbers cited above. The runtime and this documentation mirror are proprietary. Reproduction commands point at the licensed engineering checkout, not at this website.
